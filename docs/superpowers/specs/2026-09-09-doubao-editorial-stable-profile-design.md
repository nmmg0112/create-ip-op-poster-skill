# 豆包杂志式稳定出图适配设计规格

日期：2026-09-09  
状态：方案已确认，待书面规格复核  
项目：create-ip-op-poster

## 一、背景与结论

两次真实测试表明：Aime 的 Image2 使用当前通用视觉导演流程时表现较好；豆包使用当前 Seedream 5.0 Pro 适配时，出现了误用 4.5、人物资产未持续绑定、玻璃分舱与霓虹卡片墙、玩法信息不足、反复生成以及用代码承担视觉设计等问题。与此同时，豆包上一个版本曾产生一张明显更成熟的招商海报：大标题、人物群像、真实案例拼贴和杂志编辑感形成统一画面。

因此不回退整个 Skill。Aime 和通用 Agent 保留当前动态视觉导演；豆包新增一个基于真实 good case 的“杂志式稳定出图适配”。它复用旧版的优点，同时保留新版的自动开场、人物确认、内容方案、一次正式生成、版本锁定和 QA 防线。

## 二、平台分流

- **Aime**：继续使用当前 Image2 动态视觉导演版，不限制为固定杂志式结构。
- **通用 Agent**：继续根据 Brief、人物和视觉参考自主选择合理构图。
- **豆包**：默认使用 Seedream 5.0 Pro 和杂志式稳定构图。只有用户明确指定其他版式，才退出该默认母版。

不同平台共享相同的 Brief 分析、人物素材确认、内容玩法标准和最终 QA；只在生图模型、Prompt 编译和默认构图语法上分流。

## 三、Seedream 5.0 Pro 模型硬门

豆包进行任何生成式图片操作前，必须先验证当前调用模型。

1. 正式海报每次调用都显式指定 `Seedream 5.0 Pro`，不得使用“默认模型”。
2. 调用前向用户显示一次真实状态：`本次生图模型：Seedream 5.0 Pro`。这不是确认点，用户不需要回复。
3. 未验证模型时不得开始生成，也不得声称已经使用 5.0 Pro。
4. 5.0 Pro 不可用或调用失败时，正式海报停止，不得降级到 4.5 或其他默认模型。
5. 人物原图本身已是透明底或干净白底时，人物确认图可以使用确定性抠图、缩放和拼贴，不经过生成式重绘；只要涉及生成式人物处理，就同样必须使用 5.0 Pro。
6. 若豆包环境存在平台原生的 `seedream-50` 与 `creative-design` 能力，正式生图前优先读取和使用；不存在时才使用 Skill 内置豆包执行合同，不能假装已调用。

## 四、人物资产强绑定

人物确认后建立 `ApprovedPersonAssetSet`，记录：

- 稳定人物编号与公开昵称；
- 用户确认过的原图、独立抠图或组合图；
- 人物数量、不可拆分关系和最终批准版本；
- 最终呈现方式：聚合群像、按玩法分组或混合式。

豆包正式生图必须实际上传并引用批准的人物资产，不能只把人物姓名写进 Prompt。默认杂志式海报优先使用确认过的高清人物组合图作为核心参考；用户明确选择按玩法分组时，使用批准的独立人物素材，并在方案卡中直白写明“最终不使用聚合群像”。

人物白底预览仍只确认身份、数量、比例、完整性和边缘，不自动锁定海报坐标。但内容方案必须明确写出最终人物呈现方式，避免用户把“人物确认”误解为只确认姓名。

## 五、豆包默认视觉母版

豆包采用“大标题＋人物主视觉＋案例拼贴＋玩法说明”的杂志编辑式构图。它是一套信息与视觉关系，不是固定坐标模板。

### 5.1 必须保留的视觉关系

- 大标题建立第一眼主题，具有明确字体气质与版面张力；
- 人物是第一或第二视觉焦点，多人使用聚合群像，单人使用明星／达人主视觉；
- 案例截图以拍立得、胶片、画报裁片或内容窗口方式融入画面，而不是整齐头像网格；
- 标题、人物与案例允许适度跨区、交叠和穿插，形成一个完整画面；
- 玩法说明与对应案例靠近，让招商方能把“谁、做什么、案例依据”连起来阅读；
- 颜色、字体、材质、光线和案例拼贴语言随 Brief 变化。

### 5.2 禁用的默认语法

除非用户明确要求且提供参考，不使用：

- 三等分玻璃舱；
- 霓虹控制台、全息 UI 和数据驾驶舱；
- 等宽卡片墙、后台面板或 PPT 三栏；
- 人物缩成模块角落里的小头像；
- 用圆角矩形、色条和阴影替代真实视觉设计；
- 先生成无字空底图，再由代码建立整套版式。

“科技炫酷”默认转译为真实行业场景中的大片感、金属材质、克制冷色、展陈灯光、速度线或结构张力，不自动等同于赛博霓虹。

## 六、首版内容密度

正式首版必须同时包含主题、人物、玩法和案例，不再先出一张只有标题与群像的空内容海报。

每个玩法区至少包含：

- 玩法标题；
- 对应成员；
- 一至三行具体玩法说明。

玩法说明不限制为一句。根据用户选择的少／中／多文字密度，允许补充：真实场景或人物关系、关键动作／互动／挑战、产品或项目如何自然进入、案例依据、合作价值或内容结果。文字应形成可读层级，不写成长段说明书，也不为了减少错字而删除招商所需信息。

有案例素材时，默认选择 4—6 张最有代表性的真实截图，并与玩法一一对应；不得虚构数据或案例。没有案例时不造图、不伪造案例区，可以扩大人物和玩法区域，同时标记内容贴合度有限。

## 七、一次生成与修改规则

用户回复 `选 1 生成` 后，豆包从当前锁定规格编译一次完整海报 Prompt，首个正式产物就是可交付的 16:9 横版招商海报。

- 不先生成排布稿、无字底图、人物底图或空舞台；
- 不因为模型错字自动连续生成第二张；
- 用户明确说“重新来一版”并给出新要求时，将该要求整理成新的锁定版本，只正式生成一次；
- 不在一次修改中依次生成“新版、无字版、叠字版、聚合版、精装修版”；
- 用户认可整体海报后，姓名、Logo、固定中文、报价和单个案例才允许局部修正；
- 代码只允许承担已接受画面上的确定性局部替换，不得承担背景、卡片墙、主构图或整体视觉设计。

## 八、豆包专用 QA

成图后必须实际查看图片，并按以下标准判断：

- 模型调用证据确认为 Seedream 5.0 Pro；
- 16:9 横版；
- 批准人物素材已实际参与生成；
- 人物数量正确，无明显错脸、漏人、重复和串脸；
- 人物具有足够视觉面积，不是卡片配图；
- 大标题、人物、案例和玩法形成统一杂志画面；
- 每个玩法包含成员和足够说明，不只有抽象标签；
- 案例与玩法对应，未虚构数据；
- 没有玻璃分舱、后台面板和 PPT 卡片墙；
- 没有无意义空白，前中后景和阅读路径成立；
- 未经用户授权没有第二次正式生成。

任何硬项失败时不得使用“整体效果不错”“这一版效果很好”等自我评价。应直接指出失败项，保留当前文件并停止自动重试。

## 九、回归测试

实施后至少覆盖以下场景：

1. 豆包当前默认模型为 4.5：正式生成被拦截，不发生降级调用。
2. Seedream 5.0 Pro 报错：人物干净原图可确定性拼贴，正式海报停止。
3. 用户输入“科技炫酷”：输出真实行业大片语法，不出现默认玻璃舱或霓虹控制台。
4. 多人＋案例＋中等文字密度：首版包含人物群像、4—6 张案例以及每个玩法一至三行说明。
5. 用户只说“字再多一点”：增加玩法解释层级，不切换为代码卡片墙。
6. 用户要求整体重做：只建立一个新锁定版本并生成一次。
7. 单人海报：自动转为“大标题＋单人主视觉＋案例拼贴”，不制造多人群像。
8. Aime 与通用 Agent：原有动态视觉导演行为和测试继续通过，不受豆包母版影响。

## 十、实施边界

本次只修改豆包平台分支、共享的人物资产绑定字段以及相应测试。Aime 和通用版的构图自由度、当前 Image2 流程、自动新手开场与两次确认规则保持不变。豆包适配的目标是优先获得稳定、美观、可复现的招商海报，不追求和 Aime 逐像素一致。
