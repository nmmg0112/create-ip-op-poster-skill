# 傻瓜版 IP/OP 海报 Skill 重构设计

## 目标

让不熟悉 Agent、生图模型或设计术语的机构用户，只需要提供素材并做两次自然确认，就能得到一张以内容玩法为核心、默认 16:9 横版、可直接查看的完整招商海报。

本次重构以 2026-08-30 的成功 IDA 示例为基准流程：先确认人物拼贴，再结合 Brief 和案例提炼主题与玩法，最后把人物拼贴、案例和完整内容一次交给生图模型生成整张海报。只有用户明确要求素材完全不变时，才切换到“艺术底图＋原素材拼接”。

## 已确认的产品决定

1. 默认直接生成完整海报，不先生成空底图，不要求用户确认排布稿。
2. 默认使用已确认的人物拼贴、案例截图、Brief、主题、玩法和视觉要求作为生图参考，最大程度保持人物与案例，但不承诺逐像素保真。
3. 只有用户明确要求人脸、案例文字、Logo、数据或固定中文完全不变时，才使用严格保真路线。
4. 人物素材确认始终保留，并且早于内容方向和海报生成。
5. 玩法先于画面。未形成具体玩法时禁止调用正式海报生图。
6. OP 默认输出 16:9 横版；只有用户明确要求其他比例时才改变。
7. 用户不需要理解或选择模式 A/B、蒙版、底图、图层、Prompt 长度或模型能力。
8. 成图后的 Logo、文字、价格、案例替换等精确修改不得整图重绘，只能局部贴图或图层修改。
9. 最终必须直接展示可查看的海报预览并提供可用文件，不能只给工作区路径或宣布“已完成”。

## 用户看到的最短流程

```text
上传人物原图
  -> 确认人物素材
  -> 上传/补充 Brief、案例、Logo、固定文案
  -> 确认内容方案并直接授权生成
  -> 完整海报生图
  -> 最终视觉 QA 与交付
```

默认只有两个确认点。

### 确认点一：人物素材

多人物继续使用用户确认过的原话：

```text
把以上人物/动物 拼贴成组合形式，有交叠感，不要并列罗列出来，我要做海报用，横版，其他顺序不重要，横版白底，不要改变任何一个人的长相，抠人物图即可 注意人物不能重复，且人物大小调整一致一些
```

向用户只展示一张横版白底人物组合预览。核对人物／动物身份、数量、重复、遗漏、大小、身体完整性、交叠、遮脸和明显原图残边。人物素材确认不等于最终海报排布确认。

用户可直接回复：

```text
人物没问题
```

### 确认点二：内容方案＋生成授权

人物通过后，Skill 先读取 Brief 和案例，完成内容判断，不立即生图。默认给出一个推荐方案和一个明显不同的备选方案；每个方案只展示：

- 创意主题与一句主题文案；
- 具体玩法分组；
- 每组达人及其案例依据；
- “谁在什么场景做什么，产品如何进入”的一句玩法；
- 16:9 横版的第一视觉与视觉世界；
- 案例、Logo、报价或权益是否进入海报；
- 默认整图生成的保真边界。

推荐方案排在第一。用户可直接回复：

```text
选 1 生成
```

这条回复同时完成方向选择、方案确认和正式生图授权。不再增加模式选择、完整 Prompt 确认或排布确认。用户要求查看完整 Prompt 时可以展示，但不新增确认门槛。

## 内容玩法硬门槛

正式生图前，每个玩法必须具备：

```text
玩法标题
明确成员
账号/案例依据
具体场景或人物关系
动作、冲突、互动或反转
产品/项目自然进入方式
海报上的一句短文案
```

多人项目应按内容生效机制或商业逻辑分组，不能为了人数平均而强行分组。案例图首先用于提取账号真实内容，再决定是否作为视觉证据进入海报。没有案例时可以继续，但必须降低玩法贴合度声明，不能伪装成深度定制。

以下任一情况存在时，正式生图必须被拦截：

- 只有主题口号，没有具体玩法；
- 达人没有玩法归属；
- 玩法只有适配品类，没有场景、动作或产品进入方式；
- 存在未解决的问题或互相矛盾的固定要求；
- 画幅未明确且执行参数不是默认 16:9 横版；
- 使用“高级感、科技感、商业感”等抽象词替代具体视觉世界。

## 默认生产路线：完整海报一次生成

默认把以下内容一起交给生图模型：

- 已确认的横版白底人物拼贴图；
- 用户提供的案例截图和 Logo；
- Brief 中的事实；
- 已确认的主题、玩法分组、短文案和商务信息；
- 视觉案例提炼出的结构、密度和气质语法；
- 画幅、第一视觉、阅读顺序、配色、材质和景深；
- 少量关键禁令。

模型直接生成一张 16:9 完整招商海报，人物、案例、主题、玩法、数据和商务留白同时进入一个统一画面。不得先生成空背景、空舞台、留洞底图或程序化排版页。

Prompt 必须最少充分，优先级为：

```text
主题与内容玩法
人物与案例的视觉角色
完整艺术构图和信息层级
固定文案与商务信息
人物/案例尽量不改的要求
少量关键禁令
```

默认路线必须向用户说人话披露：整图生图会尽力保持人物和案例，但可能产生细节变化；若必须完全不变，可以改用严格保真制作。不得声称整图生成实现了逐像素保护。

## 例外生产路线：严格保真

只有用户明确表达以下需求时自动切换：

- 人脸或动物必须完全不变；
- 案例截图的画面、文字或数据一个字都不能改；
- Logo、固定中文或报价必须准确；
- 正式提报要求原素材严格保真。

严格保真路线由生图模型先生成包含完整场景、玩法关系、材质、光影、前中后景和视觉动势的艺术底图，再覆回确认过的人物、完整案例、原 Logo 和准确中文。底图不能只是空背景，也不能由 SVG、HTML、Canvas、PPT、规则矩形或程序化网格代替。

严格保真是后台路由，不要求新手理解技术模式。只有保真要求会改变预期效果或当前平台能力不足时，才用一句话说明差异。

## 精确后期修改

完整海报生成后，以下需求必须使用局部贴图或独立图层修改：

- 添加、替换或移动 Logo；
- 修改准确中文、报价或权益；
- 替换案例截图；
- 只移动、缩放一个已有元素。

不得把整张成稿再次交给生图模型完成精确修改。修改后必须证明非目标区域未变化；平台没有局部合成能力时输出明确交接，不得用整图重绘冒充局部修改。

## 视觉导演与参考库

视觉导演成为顶层必经动作，而不是可选参考。生成方案前必须实际打开 2—4 张互补案例原图，分别承担结构、密度和气质参考；不得只读文字索引或按颜色机械匹配。

每次至少确定：内容关系、版式家族、人物呈现方式、信息密度、第一视觉、阅读路径、前中后景、Brief 专属视觉母题、配色依据和主要留白用途。数码项目不能默认科技蓝，节日项目不能默认套用旧节庆元素。

## 最终 QA

正式生图前先做不消耗生成次数的预检；正式生图后必须查看实际成图，而不是只检查 Prompt。

以下任一项是硬失败：

- 默认任务不是 16:9 横版；
- 主题或具体玩法缺失；
- 人物、案例、玩法之间没有清楚关系；
- 第一视觉不明确；
- 像 PPT、网页后台、规则卡片墙或空背景；
- 全部内容在同一平面，没有前中后景；
- 人物明显错脸、漏人、重复或出现陌生人；
- 案例出现严重变形、乱码或虚构数据；
- 最终图片无法直接预览或下载。

默认只正式生成一次。QA 失败时必须诚实说明问题和负责阶段，不自动消耗第二次生成；用户明确要求重做后才再次生成。

## 跨平台降级

- 有完整海报生图能力：执行默认整图生成。
- 有生图且有分层合成能力：可以执行默认路线或严格保真路线。
- 只有生图、没有分层合成：默认路线可完成；严格保真需求必须交接。
- 没有生图能力：只输出内容方案、完整 Prompt 和素材说明，不得生成 SVG、PPT 或程序化信息板冒充海报。

## 需要删除的旧设计

- 面向用户的模式 A/B 选择卡；
- `direction_and_mode_pending`；
- 独立的 `prompt_pending` 确认轮；
- 强制展示完整 Prompt；
- 排布稿和“排布通过”；
- 默认空底图＋后贴素材；
- 把人物白底图当成最终排布锁定；
- 生成后用整图重绘完成 Logo 或文字精确修改。

## 状态机

```text
intake
  -> person_material_pending
  -> content_plan_pending
  -> production
  -> qa
  -> complete

严格保真但平台能力不足 -> handoff
```

## 回归场景

1. 七位游戏剧情达人：先确认人物，读取七张案例，形成三组玩法，以浅蓝夏日风生成 16:9 完整海报。
2. 数码 badcase：缺少具体玩法或生产参数为 3:4 时必须在生图前拦截，不能生成“竖版科技空舞台”。
3. 精确 Logo 修改：在第一版成稿右上角加入原 Logo，非目标区域保持不变，不得整图重绘。
4. 严格保真项目：明确要求人脸、案例和中文完全不变时，自动切换艺术底图＋原素材合成。
5. 无案例项目：可以继续，但明确达人玩法贴合度有限，不虚构账号机制。
6. 无生图平台：输出交接包，不生成程序化伪海报。

## 验收标准

1. 新手默认只看到人物确认和内容方案＋生成授权两个确认点。
2. 默认路径不询问模式 A/B，不使用蒙版、底图、图层等技术词解释普通流程。
3. 未形成具体玩法时不能调用正式生图。
4. 未指定比例时始终使用 16:9 横版，执行参数与确认卡一致。
5. 默认一次生成完整海报，不先生成空底图。
6. 严格保真只在用户明确要求时启用。
7. Logo、文字、报价、案例等精确修改不会整图重绘。
8. 视觉导演实际打开参考原图，并能说明结构、密度和气质借鉴边界。
9. QA 检查实际成图，并拦截无玩法、竖版、PPT 感、空背景和交付不可用。
10. Skill、Plugin、本机安装版和发布包使用同一流程合同。

## 非目标

- 不承诺整图生图可以逐像素保持人物、案例、Logo 或中文。
- 不要求外部机构理解模型、蒙版、图层或文件哈希。
- 不为普通用户增加第三个确认点。
- 不用固定模板取代视觉导演和生图模型。
