# Aime／豆包视觉导演与新手开场白设计规格

日期：2026-09-08  
状态：方案已确认，等待书面规格审阅  
项目：create-ip-op-poster

## 一、目标

在不改变现有“两次确认”主流程的前提下，解决两个问题：

1. 把 Codex 成功案例中的视觉导演能力固化为跨平台执行合同，让 Aime 的 Image2 和豆包的 Seedream 5.0 Pro 能获得尽量一致的策划、构图与生图输入。
2. 降低新手使用门槛。用户不需要记启动 Prompt，不需要理解平台适配文件，只需上传 Skill 包并用一句自然语言开始。

本次优化不承诺不同模型逐像素生成相同画面，但要求平台得到相同的需求收口、视觉判断、内容玩法、执行 Prompt 结构、生成次数控制和 QA 标准。

## 二、核心判断

模型能力接近不等于结果自然接近。影响结果的主要变量还包括：

- 平台是否完整读取了 Skill 和引用文件；
- 是否把零散聊天直接交给生图模型；
- 生图前是否明确第一视觉、内容玩法、信息密度和景深；
- 是否使用了完整、简洁且无矛盾的执行 Prompt；
- 第一版通过后是否锁版；
- 修改时是局部修正还是整图重绘。

猫咪 bad case 中，用户补充要求较慢、较散确实增加了漂移风险，但 Skill 也负有主要的流程责任：它应在正式生图前主动收拢需求，在用户选择方案后冻结本轮规格，并在后续修改时保护已经成功的版本。

## 三、产品结构

采用“一个通用导演核心＋平台执行适配”的结构。

### 3.1 通用导演核心

通用核心继续由 `SKILL.md` 和共享引用文件承担，统一规定：

- 人物素材确认必须最先完成；
- OP 默认使用 16:9 横版；
- 必须形成真实、具体的内容玩法；
- 必须结合 Brief、人物特点、案例证据和用户视觉偏好；
- 生图前完成视觉导演判断和美观预检；
- 默认只正式生成一张完整海报；
- 不生成排布稿，不增加完整 Prompt 确认；
- 第一版通过后锁版；
- 精确文字、Logo、案例或单一元素修改不得整图重绘；
- 最终检查实际图片，而不是只检查 Prompt。

### 3.2 Aime 执行适配

新增自包含文件 `references/platforms/aime-executor.md`。它必须在不继续跳转其他引用文件的情况下，直接告诉 Aime：

- 使用 Image2 完成人物素材处理和正式海报生成；
- 不把整段聊天记录原样交给生图模型；
- 先把用户输入整理为锁定规格，再编译成简洁执行 Prompt；
- 正式生成前运行视觉导演预检；
- 调用 Image2 时只传递当前版本的素材、锁定内容和必要约束；
- 第一版通过后进入锁版状态；
- 局部准确修改不得整图重画；
- 无法满足多图参考、局部编辑或严格保真时必须明确提示。

### 3.3 豆包执行适配

新增自包含文件 `references/platforms/doubao-executor.md`。它必须直接规定：

- 人物素材处理和正式海报生成使用 Seedream 5.0 Pro；
- 用户不需要发送固定启动 Prompt；
- Skill 被读取后自动输出新手开场白；
- 多人素材先建立稳定人物编号和昵称映射，防止漏人、重复和串脸；
- 生图前把零散聊天整理为锁定规格；
- 正式生成只使用当前锁定版本，不能把已废弃要求继续带入；
- 第一版通过后锁版；
- 精确修改优先局部处理，不能为改一个名字重绘整张海报；
- 当前会话不能使用 Seedream 5.0 Pro、多图参考或图片编辑时，先说明能力限制。

## 四、自动新手开场白

开场白属于 Skill 行为，不属于用户必须复制的指令。

用户最小操作为：

1. 上传完整 Skill 压缩包；
2. 说“帮我安装并告诉我怎么使用”“用这个 Skill 帮我做海报”或同等自然表达。

Skill 被读取后自动回复：

> 你好，我会带你完成一张 IP／OP 招商海报。
>
> 流程很简单：先确认人物素材，再选择一个内容与视觉方向，最后一次生成完整海报。
>
> 请先上传人物／动物原图。人物肖像质量会直接影响海报效果；如果有达人案例截图，也建议一起上传，它能帮助我提炼真实的内容玩法。
>
> 你还可以顺手告诉我：
>
> 【主题／Brief】  
> 【喜欢的风格】不知道可以写“你推荐”  
> 【文字密度】少／中／多  
> 【必须出现的文字】
>
> 多人示例：4 位达人｜运动赛事主题｜红蓝对撞、大片感、高张力｜中等文字密度｜包含主题、项目背景、两组玩法和人物姓名。
>
> 资料不全也没关系，先把人物图片发给我就可以。

开场白只出现一次。用户已经上传素材并说明需求时，Skill 不重复展示完整教学，而是直接整理已有信息并推进人物素材确认。

## 五、渐进式输入规则

模板是提示，不是表单门槛。

- 用户可以照模板填写，也可以用自然语言描述；
- 用户写“你推荐”时，视觉导演根据 Brief 和案例判断；
- 用户没有填写文字密度时，默认使用“中等”，再根据玩法数量调整；
- 用户没有案例时可以继续，但要说明玩法贴合度有限；
- 缺少非关键材料时继续推进，不反复追问；
- 每轮最多追问一个真正会改变结果的问题；
- 已经提供的信息不得重复询问。

人物肖像和案例说明必须使用普通中文：人物肖像质量决定主视觉是否清楚可信；案例帮助识别达人真实场景、人物关系、叙事方式、笑点和反转，使玩法不悬浮。

## 六、锁定规格与导演编译

正式海报生成前，Agent 必须在内部形成一份 `LockedPosterSpec`，但默认不向新手展示技术名称。

最少包含：

- 当前版本号；
- 画幅与用途；
- 人物、动物、案例、Logo 和固定文字清单；
- 主题和项目背景；
- 单人玩法或多人分组玩法；
- 第一视觉；
- 人物呈现方式；
- 信息密度；
- 配色、材质、光线、景深和动势；
- 阅读顺序；
- 必须出现和禁止出现的内容；
- 当前采用的参考案例语法；
- 正式生图次数。

用户回复“选 1 生成”后，当前方案被锁定并授权一次正式生成。Agent 必须从 `LockedPosterSpec` 编译生图 Prompt，不得继续混入早期已否决方向、解释性对话或平台操作说明。

执行 Prompt 采用三段式最少充分结构：

1. **必须准确的事实**：主题、人物、玩法、固定文字、案例对应和画幅；
2. **视觉导演指令**：完整视觉世界、第一视觉、人物动作与关系、层级、信息密度、材质、光影、景深和阅读动势；
3. **少量关键禁令**：不得竖版、不得无玩法、不得 PPT 感、不得漏人／重复／串脸、不得出现无意义空白。

## 七、成功案例包

新增跨平台可读取的两个 Golden Case，不只保存最终 Prompt：

### 7.1 多人高张力案例

保存：

- 用户原始输入；
- 人物与阵容要求；
- 导演判断；
- 锁定规格；
- 最终执行 Prompt；
- 成图预览；
- 成功原因：第一视觉强、人物尺度有主次、场景具有冲突和动势、玩法可见、文字密度合适、前中后景完整。

### 7.2 单人高质感美妆案例

保存：

- 用户原始输入；
- 人物素材选择和裁切要求；
- 导演判断；
- 锁定规格；
- 最终执行 Prompt；
- 成图预览；
- 成功原因：人物是唯一主视觉、画面简洁但不空、材质和光线高级、文字克制、主题与人物气质一致。

案例只用于教授判断方法，不能变成固定赛事风或固定美妆风模板。

## 八、版本保护与修改分流

正式成图产生后建立 `PosterVersionLock`：

- 保存当前成功版本；
- 用户说“这版很好”“通过”或同等表达后，标记为锁版；
- 改姓名、Logo、固定文字、报价、案例或单个标签时走局部修改；
- 调整整体风格、主题、主要构图、人物组合或背景时，回到内容方案阶段；
- 需要整图重生成时先说明会产生新的整体版本，不能覆盖已通过成图；
- 新生成失败时仍保留上一版成功文件。

## 九、用户流程

```text
上传 Skill 包并说一句自然语言
  -> Skill 自动说明用法并索要人物素材
  -> 生成人物白底组合预览
  -> 用户确认“人物没问题”
  -> Agent 整理 Brief、案例、风格与文字需求
  -> 视觉导演形成两个真正不同的内容／视觉方向
  -> 用户回复“选 1 生成”
  -> Agent 锁定规格并调用平台指定生图模型一次生成完整海报
  -> 实际成图 QA
  -> 用户通过后锁版；后续按修改类型分流
```

默认仍只有两个确认点：人物素材确认、内容方案选择＋生成授权。不开设排布确认、完整 Prompt 确认或技术路线确认。

## 十、失败处理

以下情况在正式生图前拦截：

- 默认画幅不是 16:9 横版；
- 没有具体内容玩法；
- 第一视觉不明确；
- 人物全部等权排排站；
- 预期结果像 PPT、后台页面或规则卡片墙；
- 文字密度明显低于用户要求；
- 当前 Prompt 混入互相矛盾或已废弃指令；
- 未选择当前平台应使用的生图模型。

以下情况成图后判为失败：

- 竖版；
- 人脸、动物身份明显改变；
- 漏人、重复、串脸；
- 没有内容玩法；
- 信息过少且画面空；
- 没有前中后景或视觉张力；
- 明显 PPT 感；
- 第一版已通过，却因一次局部修改导致整图风格、人脸或构图变化。

失败后不自动消耗第二次正式生图。先说明失败点，保留上一版，再等待用户明确要求重做。

## 十二、验收标准

1. 用户不需要复制长启动 Prompt。
2. Skill 被读取后自动说明流程、材料价值、多人示例和极简模板。
3. 用户已经提供完整信息时不会重复教学或重复提问。
4. Aime 使用 Image2，豆包使用 Seedream 5.0 Pro。
5. 两个平台在正式生图前都形成相同字段的锁定规格。
6. 生图模型只接收当前锁定版本和最少充分 Prompt。
7. 默认只有两次确认，不恢复排布确认或完整 Prompt 确认。
8. 默认输出一张 16:9 横版完整海报。
9. 多人海报有清楚分组、具体玩法、主次尺度和场景关系。
10. 单人海报有唯一人物焦点，简洁但不空。
11. 用户通过第一版后，局部修改不会触发整图重绘。
12. Golden Case 可以被 Aime 和豆包直接读取，不依赖 Codex 隐含上下文。

## 十三、非目标

- 不要求用户理解 Image2、Seedream、锁定规格或 Prompt 编译。
- 不承诺不同平台生成完全相同的像素结果。
- 不以强制长表单代替自然语言交流。
- 不增加第三个确认点。
- 不把成功案例的表面风格固定为所有海报模板。
- 不通过堆叠更长 Prompt 解决审美问题。
