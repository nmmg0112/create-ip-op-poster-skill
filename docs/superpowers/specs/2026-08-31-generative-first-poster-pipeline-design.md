# 生图模型优先的 IP/OP 海报流程改造设计

## 目标

将 `create-ip-op-poster` 从“固定坐标信息排版”改为“生图模型主导视觉”的海报生产 Skill，同时向用户提供快速生图和保真合成两种清楚、可选择的路径。取消强制排布稿确认，避免预览稿和成稿重复、无价值确认与额外出图消耗。

## 已确认的产品决定

1. 最终视觉默认由生图模型完成，不再使用固定坐标 SVG、规则色块、矩形框、系统字体和头像网格作为成稿设计引擎。
2. 向用户明确提供两种生成模式，不替用户隐式选择素材保真风险。
3. 删除 `composition_pending` 和强制“排布通过”确认。
4. 人物素材确认是两种模式共同的第一道生产门槛，必须早于创意方向和模式选择；这个确认只检查人物素材，不确认整张海报排布。
5. 人物素材通过后，才结合 Brief、案例截图和账号特征讨论主题、玩法及模式 A/B。
6. 保留一次最终完整 Prompt 确认；用户确认后默认只正式生图一次。
7. 模式 B 的视觉底图必须是生图模型直接生成的位图成品，例如 PNG、WebP 或 JPEG；不得先用 SVG、HTML、Canvas、PPT、Sharp 图形指令或其他程序化排版生成底图。
8. 代码只能在生图底图产生之后承担受保护图层的最终合成、尺寸转换和验证，不可承担整张海报的视觉设计。
9. 任一平台没有生图能力时，输出 Prompt 或交接包，不得自动退回程序化信息板。

## 用户看到的两种模式

### 模式 A：快速生图

用户提示语：

> **快速生图｜效果完整、速度快**  
> 生图模型直接完成整张海报，包括人物、截图、Logo 和中文。画面通常更统一、更有设计感，但模型可能重新绘制人物细节、截图内容、Logo 或文字，不能保证与原素材逐像素一致。

适用场景：

- 优先追求整体效果和速度；
- 用于创意预览、内部讨论或允许素材发生生成式变化；
- 用户已明确接受人物、截图、Logo 和中文可能被重新绘制。

用户选择该模式，视为对本次输出启用生成式重绘的明确授权。Skill 不得声称人物、截图、Logo 或文字已被原样保留。

### 模式 B：保真合成

用户提示语：

> **保真合成｜原素材更准确**  
> 生图模型先生成主视觉、背景、材质、光影和艺术构图，再把人物抠图、案例截图、Logo 和中文作为原始保护图层覆回。速度稍慢，但更适合正式提报和必须保持素材准确的项目。

适用场景：

- 人脸、动物、截图数据、Logo 或固定中文不能改变；
- 用于正式招商、客户提报或对素材准确性有明确要求；
- 当前平台支持抠图、蒙版和分层合成。

此模式保留素材保护规则。代码只用于把确认过的原始图层合成到生图模型生成的视觉底图中，不得用代码重新设计整张海报。

这里的“视觉底图”专指生图模型返回的真实位图：它已经包含完整的背景场景、艺术构图、材质、光影、空间层次、装饰语言和视觉动势。它不是空白模板、线框图、SVG 矢量页、HTML 截图或由矩形色块拼成的信息板。用户提供的 SVG Logo 可以作为受保护源素材使用，但程序不得自行生成 SVG 来冒充视觉底图。

## 新工作流

### 快速生图路径

```text
intake
  -> person_material_pending
  -> direction_and_mode_pending
  -> prompt_pending
  -> production
  -> qa
  -> complete
```

### 保真合成路径

```text
intake
  -> person_material_pending
  -> direction_and_mode_pending
  -> prompt_pending
  -> production
  -> qa
  -> complete
```

### 被删除的环节

- 不再设置 `composition_pending`。
- 不再要求用户回复“排布通过”。
- 不再为了确认排布生成一张接近成稿的完整海报。
- `person_material_pending` 只展示处理后的人物／动物素材，不包含最终标题、玩法、案例、Logo、背景美术或整张海报版式。
- 如用户主动要求查看布局，可以提供文字版区域说明或低成本线框示意，但它不是流程门槛，不调用正式生图，也不能作为最终成稿复制交付。
- `intake` 可以只收到人物原图，也可以一次收到人物、Brief、案例截图和 Logo。无论材料以哪种顺序到达，都先完成人物素材处理；Brief 等材料可以暂存，但不能跳过人物确认直接进入海报生成。
- 如果用户像示例流程一样先只上传人物，Skill 应直接完成人物素材，不要求用户先补齐 Brief；“人物素材通过”后再请用户提交 Brief、案例截图和其他海报信息。

## 确认点

### 1. 人物素材确认，两种模式都需要，且必须最先完成

收到人物／动物原图后，先制作一张或多张人物组合素材，并展示给用户确认。多人物默认使用以下人物处理 Prompt：

```text
把以上人物/动物 拼贴成组合形式，有交叠感，不要并列罗列出来，我要做海报用，横版，其他顺序不重要，横版白底，不要改变任何一个人的长相，抠人物图即可 注意人物不能重复，且人物大小调整一致一些
```

此时尚未选择模式 A/B，因此人物处理必须使用同一套保真底线：不把模式 A 的后续生成式重绘授权提前到人物素材阶段。可以使用 AI 抠图或图像编辑，但只要人脸、动物辨识特征或原始组合关系发生不可接受的变化，就不能送审，必须继续修正。

人物处理阶段同步产出三类文件：

- 一张横版白底组合预览图，供用户直观看人物数量、比例、交叠和整体完整性；
- 一张与预览同排布的透明底人物总图，供整组进入正式海报；
- 每个主体的独立透明抠图，供按玩法拆分、重新形成前中后景或在单人海报中使用。

人物素材确认必须检查：

- 人物／动物数量与原素材一致；
- 没有新增、遗漏或重复主体；
- 人脸、动物头部和辨识特征没有发生不可接受的变化；
- 人物大小协调，形成组合式交叠，不是并列头像名单；
- 不遮挡人脸或动物头部；
- 横版白底，边缘没有明显原图矩形、家具残边或大块空洞；
- 单人项目只确认单人抠图完整性，不强制制造群像。

结束时让用户回复：

```text
人物素材通过
```

“人物素材通过”确认的是人物身份、数量、抠图边缘、比例与可用性，也确认当前白底组合预览没有明显问题；它不锁死整张海报的人物排布。最终海报可根据玩法选择整组使用透明总图，也可使用独立透明抠图分散到不同玩法模块，不再设置额外排布确认。

快速生图模式将确认后的人物总图或独立抠图作为整张生图的主要人物参考，但仍需说明最终模型可能再次重绘人物。保真合成模式直接把确认后的透明总图或独立透明抠图作为保护图层使用；不得把白底确认图作为矩形素材贴进正式海报。

### 2. 方向与生成模式选择

只有在用户回复“人物素材通过”后，才结合 Brief、案例截图和账号特征给出 2—3 个创意方向，并说明快速生图与保真合成的差异。用户选择方向时同时选择模式，例如：

```text
选方向 1，用快速生图
```

或：

```text
选方向 1，用保真合成
```

如果用户已经给出明确主题、玩法和模式，不重复让用户做相同选择，直接整理最终 Prompt。

### 3. 最终 Prompt 确认

Prompt 同时包含内容、视觉导演结论、相对布局、素材使用方式和负面要求。它不再锁死大量精确坐标；应给生图模型保留尺度、景深、穿插和构图自由。

用户确认完整 Prompt 后进入正式制作。这个环节只展示文字 Prompt，不生成排布稿，因此不消耗一次海报生图。默认只调用一次正式生图；只有用户明确要求修改或重做时才再次生成。

方向讨论、视觉偏好和最终 Prompt 应尽量收束在一次连续决策中；不得再拆出“玩法通过”“视觉规格通过”“排布通过”等重复门槛。只要关键信息已经明确，就展示最终 Prompt 并等待一次确认。

## 生产架构

### 模式 A：端到端生图

1. 将 Brief、已确认方向、视觉案例抽象语法和全部输入素材交给生图模型。
2. 将已确认的人物总图或独立抠图作为人物参考，让模型直接完成标题、人物、案例、Logo、文字、材质和背景的一体化画面。
3. 禁止使用 SVG 页面、PPT式网格或固定前端坐标替代生图。
4. 输出时明确标记为“生成式整图”，说明素材可能发生重绘。
5. 如果用户在成图后要求“把原 Logo 原样加到右上角”或精确修改某个保护元素，不得默默再次整图重绘；先说明继续生成式编辑可能改变人物、文字和其他区域，并提供切换为保护图层覆回的做法。

### 模式 B：生图主视觉加保护图层

1. 用户确认最终 Prompt 后，第一项生产动作必须调用生图模型，生成一张完整的主视觉位图底图；不得先运行 SVG、HTML、Canvas、PPT 或规则色块渲染器。
2. 生图模型生成的底图包含背景、场景、光影、材质、装饰、容器关系、前中后景和视觉动势，但不把需要逐像素保真的人物、截图、Logo 和固定中文画死在底图里。
3. 底图为已确认的人物总图或独立抠图、截图、Logo 和中文预留自然融入的位置，但不使用规则白框或整齐头像表作为默认容器。
4. 只有在生图底图落盘后，才允许代码执行蒙版、比例缩放、图层位置、阴影衔接、文字栅格化、格式转换和导出。
5. 将确认过的透明人物总图或独立透明抠图、截图、Logo 和中文作为独立保护图层覆回。
6. 允许添加不破坏原素材的阴影、边缘光、外部描边和环境色衔接；不得重绘受保护区域。
7. 如果受保护素材无法自然融入，返回生图模型重做主视觉底图，不得改用 SVG、固定色块或规则网格把素材硬装进信息板。
8. 成图后的 Logo、固定中文或截图调整必须继续使用独立图层合成；不得把整张海报再次交给生图模型做“局部修改”。用户已经明确“右上角”等位置时可直接按安全边距落位，只有位置确实无法判断时才请用户补充标注。

## Prompt 结构调整

- 模式 A 使用一份端到端生成 Prompt，明确用户已接受生成式重绘。
- 模式 B 拆成“主视觉生图 Prompt”和“保护图层合成说明”；两者在同一轮展示给用户确认。
- 使用相对关系描述，例如“标题与人物交叠”“案例嵌入场景中”“人物形成前中后景”，避免用大量 `x/y/width/height` 锁死艺术空间。
- 固定文案仍逐字列出，但模式 A 只承诺尽力呈现，模式 B 才承诺通过独立文字图层准确落版。
- 参考案例必须转译为结构、密度和气质指令，不能只提取配色、字体或纸张纹理。

## QA 规则

### 两种模式共同检查

- 正式制作使用的是用户确认后的人物主素材或独立透明抠图；人数正确，无新增、遗漏或重复。
- 第一视觉明确；画面不像 PPT、网页后台、表格或程序化信息板。
- 有清楚的前景、中景和背景，人物、玩法与案例形成视觉关系。
- 主题、玩法和招商信息可快速理解。
- 不把低成本线框、布局示意或旧预览复制为成稿。
- 每次正式生成都记录输出；若最终文件与任一“完整海报预览”哈希相同，直接判定 `FAIL`。白底人物确认图不是完整海报预览，不参与这项重复检测。

### 模式 A

- QA 重点是主题、人物数量、主要信息、中文可读性、整体美观和明显生成错误。
- 人物、截图、Logo 和中文不做像素保真声明。
- 若出现明显错脸、漏人、多人物、乱码或 Logo 严重失真，标记具体问题，由用户决定是否再次生成；不得自动消耗第二次生图。

### 模式 B

- 必须能追溯到一次真实的生图模型底图输出；如果生产记录里只有 SVG、HTML 截图、PPT、Canvas 或程序化绘图结果，直接判定 `FAIL`。
- 人物、截图、Logo 和固定中文必须按保护图层逐项验证。
- 每次保护图层调整后，非目标区域必须保持不变；对受保护区域和非目标区域分别做像素或哈希比对，不能只凭肉眼声称“其他部分没改”。
- 背景美术与受保护图层要自然融合；“素材都对但像贴表格”仍然判定视觉失败。
- 自动验证只能证明尺寸、数量和像素一致性；美观、层级、景深与招商质感必须进行独立视觉复核。

## 跨平台行为

- 平台同时具备生图模型和分层合成：可以完整执行模式 A 或 B。
- 平台只有生图、没有分层合成：可以执行模式 A；模式 B 先生成生图位图底图，再输出包含该底图和保护图层说明的交接包。
- 平台没有生图模型：输出完整 Prompt 和素材映射，不得用 SVG、HTML、PPT或程序化色块冒充最终海报。
- Plugin、独立 Skill 和本机安装版必须使用相同模式名称、流程和风险说明。

## 实施范围

需要同步修改：

- `SKILL.md`：双模式入口、新状态机、删除排布确认、明确生图优先。
- `references/workflow.md`：两条路径、人物素材确认和确认语言。
- `references/novice-mode.md`：新手模式选择卡和低门槛回复。
- `references/prompt-template.md`：模式 A/B 两套 Prompt 结构。
- `references/material-integrity.md`：模式 A 的授权边界与模式 B 的保护规则。
- `references/platform-usage.md`：按平台能力路由两种模式。
- `references/qa-checklist.md`：模式化 QA、预览成稿重复检测和“程序化信息板”硬失败。
- `references/visual-director.md` 与 `references/layout-grammar.md`：禁止以固定网格代替主视觉；强化生图模型的构图自由。
- `examples/`、测试、Plugin 镜像和发布包：保持功能一致。

## 验收标准

1. Skill 不再包含“四个确认点一个都不能跳过”或强制“排布通过”。
2. 任意包含人物／动物素材的新任务都会先制作人物素材，并等待用户明确回复“人物素材通过”。
3. 人物素材确认早于创意方向和模式选择；用户可先只交人物，之后再补 Brief 和案例截图。
4. 人物组合预览遵循横版白底、组合交叠、大小协调、不重复、不遮脸的规则，并同步保留透明总图和独立透明抠图。
5. 快速生图可以把整张海报交给生图模型，并清楚披露重绘风险。
6. 保真合成的第一项生产动作必须生成位图主视觉底图；程序只能在底图生成后做保护图层收尾。
7. 默认只有一次正式生图调用。
8. 没有生图能力时不会退回程序化信息板。
9. QA 能拦截预览与成稿相同、PPT/画板感、无景深和人物玩法脱节。
10. Skill、Plugin 和本机安装版通过一致性测试。
11. 模式 B 在追加或移动 Logo、截图、固定中文时不会重新生成整图，非目标区域验证为未改变。
12. 模式 B 的生产记录中不存在程序化 SVG／HTML／PPT 底图，并能验证生图底图先于图层合成产生。

## 非目标

- 不保证所有生图模型都能准确生成中文或保持人物身份。
- 不为每个平台开发新的图像生成模型。
- 不取消最终 Prompt 确认。
- 不取消两种模式共同的人物素材确认。
