# 完整海报执行 Prompt

Prompt 在后台根据用户已经选择的 `ContentPlanCard` 编译。用户回复 `选 1 生成` 后直接执行，不再额外确认 Prompt；只有用户主动说“查看完整 Prompt”时才展开全文。

## 编译原则

执行 Prompt 不是越长越好，而是信息要完整、优先级要清楚。只保留会改变画面的内容，顺序固定为：

```text
主题与内容玩法
人物与案例的视觉角色
完整艺术构图和信息层级
固定文案与商务信息
人物/案例尽量不改的要求
少量关键禁令
```

删除重复规则、通用常识、空字段和互相冲突的形容词。用户名称、主题文案、Logo 文案、报价、权益和截图中的现有文字不得擅自润色或虚构。

默认执行 Prompt 控制在约 900—1600 个中文字符；复杂多人项目最多约 2200 字。超过预算时按以下顺序删除：重复禁令、通用画质形容词、已在素材映射中出现的重复说明、不会进入画面的背景信息、次要装饰。不得为了塞满字段而牺牲玩法、人物归属、第一视觉、16:9、固定文案和关键保护边界。每个玩法只保留一条完整闭环，不把模板字段逐项机械展开成说明书。

## 生图前硬门槛

只有以下项目全部明确才可编译：

- `PersonMaterialSet.approval`；
- 画幅，OP／招商主海报为 16:9 横版；只有明确的竖版渠道／适配用途才例外；
- 主题和一到两句项目背景；
- 每个玩法的标题、成员、案例依据、场景／关系、内容动作、产品进入方式和海报短文案；
- 用户视觉偏好，或系统已经根据 Brief 推荐；用户未回答可选风格问题不构成阻塞；
- 用户偏好与 Brief 的配色／材质／光影／气质合成结论；
- 第一视觉、阅读路径、人物呈现方式、信息密度、前中后景和视觉动势；
- 2—4 张已实际打开的结构／密度／气质参考及禁止复制元素；
- 案例、Logo、固定文案、报价和权益的真实使用范围；
- 后台生成路线：`whole_poster` 或 `strict_fidelity`。

出现只有口号、达人没有玩法归属、玩法没有场景、动作或产品进入方式、只剩抽象风格词、没有明确竖版渠道却要求 3:4、素材矛盾或未解决的固定文案时，返回 `content_plan_pending`，不得调用正式生图。

## 默认完整海报一次生成：`whole_poster`

用户没有明确要求素材逐像素完全不变时，使用下列结构一次生成完整海报。

```text
请设计一张 <行业/节点> 中文 IP／OP 招商海报，<批准画幅；默认 16:9 横版，建议 1920×1080 或同等比例高清尺寸>，商业提案质感，画面统一、可直接提报。

【项目主题】
项目主题：<原样保留>
主题文案：<原样保留>
项目背景：<一到两句 Brief 事实>
项目目标：<当前征集或招商要解决的事>

【核心内容玩法】
1. <玩法标题>
成员：<公开昵称与 P 编号>
案例依据：<A/C 编号及可见内容特征>
玩法：<谁在什么场景，通过什么动作、互动、冲突或反转展开内容，产品/项目如何自然进入>
海报短文案：<一句>
视觉呈现：<人物动作、场景角色、相对尺度、所属前/中/后景，以及和案例或其他人物的连接>
案例使用：<C 编号、是否进入成图、完整显示方式；不进入则说明只用于分析>

<逐组写完，不合并、不漏人；每组都要和其他组有清楚差异>

【人物与素材】
人物／动物：<P 编号 -> 公开昵称 -> 所属玩法 -> unified-ensemble 才可使用同排布透明总图；grouped-by-play、independent-cutouts、hybrid-hero-groups 必须使用原图或独立透明素材>
案例截图：<C 编号 -> 所属玩法 -> 视觉作用 -> 位置关系；仅列要进入海报的截图>
Logo：<L 编号 -> 位置 -> 排列 -> 相对大小>
固定文案：<T 编号 -> 完整原文 -> 层级与位置>
报价／权益：<只有用户提供并要求展示时才写>

最大程度保持人物与动物的长相、数量、发型、表情、服装、姿势、品种、毛色和原始组合；不要新增、遗漏或重复主体。案例图尽量保持原画面和文字，不虚构数据。整图生图可能产生细节变化，不承诺逐像素保真。

【完整艺术构图】
内容关系：<并列/顺序/主次/场景/中心发散/证据/矩阵/情绪宣言>
版式家族：<概念场景/群像主视觉/玩法分舱/路线阶段/矩阵档案/编辑拼贴或新结构>
第一视觉：<对象、相对尺度、画面位置和视觉动作>
阅读路径：<第一视觉 -> 主题 -> 玩法 -> 案例/数据 -> 合作信息>
人物呈现：<统一群像/按玩法分组/独立人物/主视觉＋辅助分组>
信息密度：<低/中/高，以及如何保证可扫描>
前景：<引导、交叠或遮挡衔接>
中景：<人物、核心玩法和关键场面>
背景：<完整场景、空间、材质和氛围>
视觉动势：<光路、视线、动作、弧线、景物或材质如何引导阅读>
留白用途：<聚焦、分隔、呼吸或引导；不得留下空舞台>

【视觉风格】
用户偏好：<用户原话或“由系统推荐”>
Brief 依据：<主题、场景、人物行动、受众情绪或品牌规则>
合成结论：<两者如何共同决定配色、明度、冷暖、材质、光影、景深、标题能量和装饰边界；冲突时说明调整>
主背景与强调色：<颜色角色与面积关系>
场景和材质：<具体可见空间、物件、表面质感>
光影和景深：<主光方向、接触阴影、层次>
装饰：<只列服务主题的元素和使用上限>

【信息层级】
人物或关键场面是第一视觉；主题和主题文案为第二阅读锚点；具体玩法是正文主体；项目背景、案例和合作信息降级。人物尺寸不得被大段文字压过。玩法区域可以高密度，但不能使用等权卡片墙、系统后台或 PPT 式规则矩形。

【参考边界】
结构参考：<案例 ID，只写借鉴的阅读路径/区域关系>
密度参考：<案例 ID，只写借鉴的信息节奏/扫描方式>
气质参考：<案例 ID，只写借鉴的色彩关系/材质/标题能量>
不得复制任何参考图的标题、文案、Logo、人物排布、专属容器、印章、标志性装饰或独特符号。

【关键禁令】
除非批准画幅明确用于竖版渠道／适配，否则不要生成竖版或 3:4；不要做空科技舞台、空背景、网页后台、PPT 页面、线框稿、头像网格或等权卡片墙；不要让人物与玩法分离；不要遮脸或动物头部；不要密集小字；不要留下无意义空白；不要虚构达人、客户、数据、价格、权益或合作方式；不要把文件名后缀当作昵称。

【输出】
只输出一张符合批准画幅的完整招商海报预览；未批准例外时就是 16:9 横版。人物、主题、背景、玩法、案例/数据和商务信息必须在同一个统一艺术画面中完成。默认只调用一次正式生图，`formal_generation_count: 1`。不得先生成空背景，不得生成排布稿、空底图、留洞底图或第二张相同海报，不自动消耗第二次生成。
```

### 默认路线素材披露

在方案卡中只用一句话说明：`整图生成会尽量保持人物和案例，但可能有细节变化；如果人脸、截图文字、Logo 或固定中文必须完全不变，请告诉我，我会切换严格保真制作。`

不要要求用户选择技术模式，也不要声称生成式整图实现像素保护。

## 例外路线：`strict_fidelity`

只有用户明确要求以下任一项完全不变时自动启用这一后台路由：人脸／动物、案例画面或文字、Logo、真实数据、固定中文、报价或权益。用户不需要理解路线名称。

### 第一段：艺术位图底图生图

```text
基于已确认的主题、玩法、16:9 构图、视觉偏好与 Brief 合成结论，先用生图模型生成一张完整 PNG、WebP 或 JPEG 艺术底图。

若平台支持蒙版：先把原人物、完整案例、原 Logo 和准确文字按计划位置放入内部锁定画布，并锁住所有保护像素；只在未保护区域生成艺术环境。输出必须是围绕真实素材形成的完整位图世界，随后再用原保护图层覆回校验，不向用户展示中间画布。

若平台不支持蒙版：生成包含台面、地面、景物、光路、前景遮挡和自然接触面的完整艺术底图，再覆回原素材；这种能力边界必须进入 QA，重点检查人物、截图与场景是否像后贴上去。

底图必须已经具备成熟招商海报的完整场景、玩法空间关系、标题能量、材质、光影、前景、中景、背景、装饰语言、信息层级和视觉动势。为原人物、完整案例、原 Logo 和准确中文提供自然接触面、光线接口、遮挡关系和安全位置；蒙版路线中不得改动被锁像素，无蒙版路线中不得描摹、仿制或写出这些保护内容。

底图不能只是空背景，也不能是空舞台、留洞底图、固定矩形排版、SVG、HTML、Canvas、PPT、Sharp 绘图、头像网格、线框稿或程序化信息板。把程序图导出成 PNG 仍然不合格。

输出：一张 <像素尺寸> 的真实 <PNG/WebP/JPEG> 艺术位图。第一项生产动作必须调用生图模型。默认只进行这一次正式生图。
```

### 第二段：原素材覆回

艺术位图落盘并记录来源后，使用确定性图层合成；蒙版路线也必须把原保护图层再覆回一次，以排除边缘污染：

```text
P：<原透明人物总图或按需独立抠图 -> 位置、尺度、层级、脸部安全区>
C：<完整原截图 -> 位置、等比尺寸、层级；不得裁切、改字、改数据、调色或重绘>
L：<原 Logo -> 位置、等比尺寸、排列；保留全部元素>
T：<准确原文 -> 字体、字号、位置、层级>
```

代码只可做蒙版、等比缩放、位置、层级、非破坏性接触阴影、从艺术底图恢复的前景遮挡、文字栅格化、格式转换、导出和验证；不得补画或替代主视觉，不得改动保护素材内部像素。

生产回执至少记录：

```text
generation_route: strict_fidelity
visual_base_path
visual_base_format
image_generation_model_or_tool
visual_base_created_before_composite
protected_layer_ids
formal_generation_count
final_output_path
```

## 精确后期修改

成图后添加／替换 Logo、改准确中文、改报价权益、换案例或只移动一个元素时：

1. 不得把整张成稿再次交给生图模型；
2. 只新增、替换或移动目标独立图层；
3. 保存修改前后图；
4. 用像素差异或等价证据证明目标区域之外没有变化；
5. 无法局部合成时输出交接，不得用整图重绘冒充精确修改。

## 执行前最后检查

- 用户已经明确批准人物素材并选择方案生成；
- 玩法闭环完整，用户视觉偏好与 Brief 已合成；
- 画幅为用户要求，未指定时为 16:9 横版；
- 所有 `P/C/L/T` 都存在且角色唯一；
- 完整 Prompt 无残留占位、重复规则或冲突形容词；
- 视觉导演预检通过；
- 正式海报生图次数仍为 0；
- 当前平台能执行所需路线；不能时进入 `handoff`，不得生成程序化伪海报。
