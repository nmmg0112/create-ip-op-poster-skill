# 跨平台使用

无论在哪个平台，`SKILL.md` 都是唯一流程规则。平台可以更换导入方式和具体工具，但不能跳过 `人物素材通过` 与生成确认卡的 `确认生成`，也不能把“会看图”“会写代码”误当成“会生图”或“会保真合成”。

## 先选使用路径

| 你使用的平台 | 推荐方式 |
|---|---|
| Codex、Claude Code 等支持 Skill 的 Agent | 安装完整 Skill 文件夹，再显式调用 |
| 豆包、Coze／扣子、WorkBuddy 等知识库或智能体平台 | 导入 `SKILL.md` 和当前阶段需要的 `references/` 文件 |
| ChatGPT 或其他普通 AI 会话 | 复制启动语，不需要先学会安装 Skill |

新手第一轮只需提供人物／动物原图。Brief、案例截图、Logo、固定文案、参考图、报价和合作权益可以同时提供，也可以在人物素材通过后补充；不要因为 Brief 暂缺而提前替用户决定方向。

## 路径一：支持 Skill 的 Agent

安装完整文件夹，并保留 `SKILL.md`、`references/`、`assets/` 和 `examples/` 的相对位置。安装后发送：

```text
请使用 $create-ip-op-poster。先处理我上传的人物／动物原图，只展示横版白底组合预览供我确认；后台保留同排布透明底人物总图，独立抠图仅在后续确有需要时生成。不要先做创意方向或海报。
```

Codex 的精简安装和启动方法见[快速开始](../examples/quick-start.md)。

## 路径二：知识库或智能体平台

1. 将 `SKILL.md` 放入系统指令或主知识库。
2. 上传当前阶段需要的 `references/` 文件，不必一次塞入全部资料。
3. 平台支持视觉知识时，再上传选中的视觉案例；不支持时，让用户在当前任务中附上参考图。
4. 加入以下入口指令：

```text
以 create-ip-op-poster 的 SKILL.md 为唯一流程规则。先只展示白底人物组合图并等待“人物素材通过”，后台保留透明总图，独立抠图按需生成；再共创方向并选择模式 A 或 B，最后展示一屏生成确认卡，只有收到“确认生成”才进入生产。完整执行 Prompt 后台保留，用户说“查看完整 Prompt”时再展开。模式 B 的第一项生产动作必须调用生图模型生成真实 PNG、WebP 或 JPEG 位图底图，之后才能覆回受保护图层；不能用 SVG、HTML、Canvas、PPT 或程序绘图代替底图。
```

## 路径三：ChatGPT、豆包或 Coze 普通会话

不会安装 Skill 也可以使用。复制 [ChatGPT／豆包／Coze 启动语](../examples/chatgpt-starter.md)，再上传人物／动物原图；Brief 可以现在提供，也可以随后补充。

普通会话只能在平台实际具备相应能力时完成生图或保真分层合成。模型能“看图”不等于能生成图片，能生成图片不等于能保持原像素。能力不足时必须走安全交接。

## 两种生产模式

### 模式 A：快速生图

由生图模型一次完成整张海报，通常更快、更统一；人物、动物、截图、Logo 和中文可能被重绘、变形或写错。结果不得声称像素保真。适合用户接受生成式变化的快速提案。

### 模式 B：保真合成

先由生图模型生成完整艺术位图底图，再用确认过的透明人物素材、完整案例截图、原 Logo 和准确中文覆回。适合正式提报或对素材准确性要求高的项目。

模式 B 的第一项生产动作必须调用生图模型。底图必须是实际落盘、可解码的 PNG、WebP 或 JPEG，并包含场景、构图、材质、光影、前中后景、装饰语言和视觉动势。不得先运行 SVG、HTML、Canvas、PPT、Sharp 绘图、固定矩形或网格渲染器来创建或代替底图。

只有底图存在并记录来源后，代码才可用于蒙版、等比缩放、位置、层级、保护图层合成、非破坏性阴影、文字栅格化、格式转换、导出和验证。代码不得补画或替代主视觉。用户提供的 SVG Logo 可以作为保护源图层，但 SVG 海报底图不合格。

默认只调用一次正式生图。生成确认卡是纯文字轮次，不消耗生成次数；首次成图失败后，先说明失败与可修范围，不自动再生成一次。

## 平台能力路由矩阵

| 平台实际能力 | 可完成的路径 | 必须停止或交接的边界 |
|---|---|---|
| image generation + layered compositing | Mode A or Mode B：可完整执行模式 A，也可先生图再覆回保护图层完成模式 B | 仍须保存 Mode B 位图来源与先后证据 |
| image generation only | Mode A；Mode B 可先生成位图底图，再 handoff protected compositing | 不得假装已完成保真人物、截图、Logo 或中文覆回 |
| no image generation | Prompt/material map only | never SVG/HTML/PPT fallback；也不得用 Canvas、Sharp、规则色块或网格程序生成信息板 |

中文版判断：

```text
生图 + 分层合成 -> 模式 A 或模式 B
只有生图 -> 模式 A；模式 B 先生成位图底图，再交接保护图层合成
没有生图 -> 只交付 Prompt 和素材映射；绝不回退成 SVG／HTML／PPT 或程序化海报
```

### 不要按产品名称猜能力

在当前会话实际验证以下问题：

1. 能否调用生图模型并保存其真实输出？
2. 能否识别真实文件格式，而不只看扩展名？
3. 能否在位图底图存在后导入透明 PNG、完整截图、原 Logo 和准确文字并保持独立图层？
4. 能否保留工具记录、时间顺序、路径、hash 和生成次数？
5. 能否在目标尺寸与高分辨率下直接检查最终图？

任何答案为否或未知，都按能力较低的路径处理。不要因为某个平台支持代码或幻灯片，就推断它支持 Mode B 主视觉生产。

## 可选线框与关系解释

用户主动要求时，可以用线框、布局草图、关系图、网格或 SVG 解释创作者与玩法的关系。这类文件必须标记为 `optional explanation only`，不调用正式生图，也不是确认门槛。它们绝不能成为模式 B 底图、完整海报预览或最终海报；生产仍须从生图模型位图开始。

## 安全交接包

平台不能完成所选模式时，标题标记为：`执行交接包——最终图片尚未生成或尚未保真核验`，并输出：

1. 当前状态、已选方向和 `generation_mode`；
2. `PersonMaterialSet` 的横版白底组合预览图、透明底人物总图、按需独立透明抠图（如有）、素材台账和批准原文；
3. 生成确认卡、完整执行 Prompt 与每个 `P/C/L/T` 的角色映射；
4. 若已生成 Mode B 底图，提供 `visual_base_path`、`visual_base_format`、`image_generation_model_or_tool` 和 base hash；
5. `visual_base_created_before_composite`、`protected_layer_ids`、`formal_generation_count`；
6. 已完成的 QA、未验证项、能力限制和唯一下一步。

没有生图能力时，交接包只包含 Prompt 与素材映射，不得附上一张由 SVG、HTML、Canvas、PPT、Sharp、固定矩形或网格渲染器伪装成的“成稿”。若这一能力限制在进入 `prompt_pending` 前已知，直接停在 `handoff`，不得再要求用户回复 `确认生成`；接手的可生图平台在真正生产前再确认 Prompt。

换窗口或换平台时，把交接包、原始编号素材和 Skill 文件一并提供。接手 Agent 先核对当前状态和证据，不重复追问已经明确确认的决定。
