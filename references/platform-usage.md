# 跨平台使用

无论 Codex、Claude Code、ChatGPT、豆包、Coze／扣子还是 WorkBuddy，用户看到的主流程都一样：确认人物素材，补充 Brief／案例和一句可选视觉偏好，再从方案卡中选择并直接生成。平台差异只影响后台能否完成生图或严格保真合成，不能增加用户必须理解的技术选择。

当前平台由 Agent 内部识别，不让用户选择适配器。Aime 读取 [Aime Image2 执行合同](platforms/aime-executor.md)；豆包读取 [豆包 Seedream 5.0 Pro 执行合同](platforms/doubao-executor.md)。其他平台继续使用本文件的能力路由。平台适配不能改变两个确认点、内容玩法门槛、16:9 默认画幅和最终 QA。

豆包是一个视觉执行特例，不是另一套用户流程：每次图片操作前显式调用 [Seedream 5.0 Pro](skill://seedream-50?type=2&id=360075272194)，并在生成前告知实际模型；默认使用“大标题＋人物主视觉＋案例拼贴＋玩法说明”的杂志编辑式构图。模型不可用时必须说明真实平台原因和降级风险，只有用户明确回复 `继续用当前模型` 才能继续，不能静默降级。Aime 保持 Image2 动态视觉导演路径，不继承该豆包默认构图。

Skill 被读取后自动发送新手开场白。用户只需上传完整包并说一句“告诉我怎么使用”或“用这个 Skill 帮我做海报”，不需要复制长启动 Prompt。

## 三种使用方式

| 平台 | 使用方式 |
|---|---|
| 支持文件式 Skill 的 Agent | 安装完整 Skill 文件夹并调用 `$create-ip-op-poster` |
| 支持知识库／系统指令的智能体 | 导入 `SKILL.md` 和当前阶段需要的 `references/` |
| 普通 ChatGPT／豆包／Coze 会话 | 复制 `examples/chatgpt-starter.md`，直接上传人物图 |

第一轮只要求人物／动物原图。Brief、案例、Logo 和固定文案可以一起给，也可以人物确认后补。

## 用户看到的统一流程

```text
上传人物原图
  -> 查看横版白底人物预览
  -> 回复“人物没问题”
  -> 可在人物确认回复里顺手写一句颜色/感觉偏好；不写则系统结合 Brief 推荐
  -> 补充 Brief、案例、Logo、固定文案
  -> 查看推荐方案和备选方案
  -> 回复“选 1 生成”
  -> 查看一张完整 16:9 横版招商海报
```

不要求用户选择技术模式，不单独确认排布稿或 Prompt，不展示蒙版、图层、哈希和模型参数。用户主动要求查看完整 Prompt 时可以展开，但不增加确认门槛。

## 后台能力路由

先实际确认能力，不按产品名称猜测：

1. 能否调用生图模型并保存真实输出；
2. 能否直接展示并检查最终图片；
3. 能否在已有位图上局部合成透明 PNG、完整截图、原 Logo 和准确中文；
4. 能否保存调用次数、文件格式、尺寸、路径和必要的前后差异证据。

| 实际能力 | 默认任务 | 明确严格保真任务 |
|---|---|---|
| 生图＋分层合成 | `whole_poster` 一次完整海报生成 | `strict_fidelity`：优先围绕锁定原素材生成艺术环境，再覆回原素材校验 |
| 只有生图 | `whole_poster` 可完成 | 先生成人工底图后交接，或直接交接完整 Prompt／素材映射 |
| 没有生图 | 交付内容方案、完整 Prompt 和素材映射 | 同样交接，不生成伪海报 |

没有生图 -> 只交付 Prompt 和素材映射；绝不回退成 SVG／HTML／PPT、程序化海报或程序化信息板。

## 默认完整海报生成

人物素材得到 `人物没问题` 或同等明确批准、玩法闭环和视觉预检完成后，用户回复 `选 1 生成` 即授权一次正式海报生图。把已确认人物、案例、Brief、玩法、视觉偏好、完整构图和关键限制一次交给生图模型，直接生成统一的 16:9 横版成品。

正式调用必须附上与 `ApprovedPersonAssetSet` 相符的批准人物图片。统一群像附批准群像／预览，玩法分组附批准独立人物素材，混合结构两类都附；只写人物名字或外貌描述不算完成绑定。

不得先生成空背景、空舞台、排布稿、留洞页、规则色块、头像网格或第二张近似成稿。默认只调用一次正式生图；失败后说明问题和负责阶段，只有用户明确要求重做才再次生成。

默认整图会尽力保持人物和案例，但可能产生细节变化。不能声称人脸、截图、Logo 或中文逐像素不变。

## 后台严格保真

用户明确说人脸、案例文字／数据、Logo、固定中文、报价或权益必须完全不变时，自动启用，不要求用户理解技术名称。

第一项正式生产动作必须调用生图模型生成真实 PNG、WebP 或 JPEG 艺术位图。优先使用锁定画布＋蒙版：先按最终计划放置原人物、完整案例、原 Logo 和准确中文，锁住这些像素，只让模型在未保护区域生成围绕真实素材的场景、玩法关系、材质、光影、前中后景、装饰语言和视觉动势；随后再用原图层覆回校验。没有蒙版能力时才先生成完整艺术底图再覆回，并把贴纸感、接触面和人物／玩法连接列为硬 QA。无论哪种能力，位图都不能是空背景或为后贴素材准备的规则洞位。

艺术位图存在后才可使用确定性工具把原人物、完整截图、原 Logo 和准确中文覆回校验。程序只可做蒙版、等比缩放、位置、层级、非破坏性接触阴影、恢复艺术底图中的前景遮挡、文字栅格化、格式转换、导出和验证，不能用 SVG、HTML、Canvas、PPT、Sharp、固定矩形或网格补做主视觉，也不能改写保护素材内部像素。

## 精确后期修改

新增／替换 Logo、修改准确文案／报价／权益、替换案例或移动单一元素时，不再调用整图生图。只修改目标独立图层，并用修改前后差异证明非目标区域未变。平台没有局部合成能力时直接交接，不得用整图重绘冒充精确修改。

用户通过成图后建立 `PosterVersionLock`。上一版成功文件始终保留；局部修改输出新文件。只有主题、整体风格、背景、核心构图或人物组合变化时，才回到方案阶段并建立新的整体版本。

## 可选线框

只有用户主动要求时，才可用线框、关系图、网格或 SVG 解释内容关系。它必须标注为“仅作说明”，不消耗正式海报生图，不构成确认门槛，也绝不能成为艺术底图、完整海报预览或最终成品。

## 安全交接包

平台能力不足时进入 `handoff`，标题写：`执行交接包——最终图片尚未生成或尚未完成保真核验`。交付：

1. 当前状态、用户已确认的人物和方案；
2. `PersonMaterialSet` 与素材台账；
3. 用户视觉偏好、Brief 合成结论和具体玩法；
4. 完整执行 Prompt 与每个 `P/A/C/L/T` 的角色；
5. 已产生的艺术位图及来源（如有）；
6. 正式生图次数、已完成 QA、未验证项和唯一下一步。

一开始就知道没有生图能力时，记录 `formal_generation_count: 0`，不要求用户再回复生成确认词，也不生成 SVG、HTML、Canvas、PPT、Sharp、色块页或头像网格冒充成稿。接手 Agent 先读取批准记录，不让用户重复确认已经明确的决定。
