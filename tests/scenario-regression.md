# 场景回归：生图优先双模式

本文件验证当前 Skill 的“人物素材先确认 + 模式 A／B”行为。状态只使用 `PASS`、`FAIL` 或 `NOT VERIFIABLE`。Markdown 规则存在只能证明静态合同；只有隔离新对话中的完整输出、图像、图层和工具记录，才能证明场景行为通过。

方向优先的旧版运行不属于本合同，不能作为新版场景的通过证据。

## 执行协议

每个场景必须在不继承其他场景结论的新对话中执行：

1. 只向测试 Agent 提供当前 `SKILL.md` 和当前阶段明确路由的 reference；不要向它展示本文件的预期答案。
2. 使用获授权的虚构 Brief 与素材夹具。保存测试输入、完整输出、当前阶段、读取的 Skill 版本和全部必要图像／图层证据。
3. 记录每次正式海报生图的工具或模型、调用顺序、输出格式、文件哈希和 `formal_generation_count`。人物素材处理不计入正式海报生图次数。
4. 在标准回复出现前验证 Agent 是否准确停在指定阶段；不得用下一轮输出倒推上一确认点已经通过。
5. 用 `references/qa-checklist.md` 逐项判定。规则存在但没有真实产物或工具记录时，必须记为 `NOT VERIFIABLE`。
6. 发现 `FAIL` 时记录负责文件、实际停留阶段和应回退阶段。修复后只重跑该场景及受影响的下游行为。

## 场景 1：只先提供人物素材

### 测试输入

> 我先只上传这些获授权的人物／动物原图，Brief、案例和 Logo 之后再给。请先把人物素材处理好。

多主体夹具使用稳定 ID `P01...`，并至少包含一个需要检查交叠、人数和重复风险的组合。

### 预期停留阶段

`person_material_pending`

### 预期行为

- 不要求先补 Brief，也不先给创意方向或模式选择。
- 多主体处理使用以下完整 Prompt，不能改写或省略：

```text
把以上人物/动物 拼贴成组合形式，有交叠感，不要并列罗列出来，我要做海报用，横版，其他顺序不重要，横版白底，不要改变任何一个人的长相，抠人物图即可 注意人物不能重复，且人物大小调整一致一些
```

- 同步产出并保存 `横版白底组合预览图`、与预览同排布的 `透明底人物总图`、每个唯一主体或不可拆原始组合的 `独立透明抠图`。
- 核对人物／动物数量、身份、原始组合、脸和动物头部、比例、交叠、遮挡、边缘、家具残边、遗漏与重复；单人夹具不强制制造群像。
- 白底预览只确认人物素材可用性，不出现最终标题、玩法、案例、Logo、背景美术或完整海报版式。
- 以可复制回复 `人物素材通过` 收尾。在收到这句明确确认前，不进入 `direction_and_mode_pending`。

### 通过所需直接证据

- 三类人物素材文件及其尺寸、透明通道和稳定 ID 对照；
- 源素材与处理结果的身份、数量、边缘和重复检查；
- 显示停在 `person_material_pending` 的完整对话。

当前结果：`NOT VERIFIABLE`。尚未用当前版本在隔离新对话中运行并取得上述图像证据。

## 场景 2：模式 A 快速生图

### 前置条件与测试输入

先向新对话提供已核验的 `PersonMaterialSet` 及其明确确认记录 `人物素材通过`，再提供一份虚构的单达人 Brief、一张案例截图和一个 Logo。让 Agent 给出方向后回复：

> 选方向 1，用模式 A

Agent 展示完整 Prompt 后再回复：

> 确认生成

### 预期停留阶段

- 正式生图前必须停在 `prompt_pending`。
- 只有成图与全部硬性 QA 通过后，最终才停在 `complete`；任一硬失败必须停在 `qa` 或回退到负责阶段，不能自动消耗第二次正式生图后宣称完成。

### 预期行为

- 人物素材确认之后才讨论方向和模式；模式卡明确披露人物、截图、Logo 和中文可能被生成式重绘。
- 最终 Prompt 把整张海报交给生图模型，映射人物、案例、Logo、固定文案、玩法、艺术方向、相对构图、负面约束与验收条件，并逐项列出允许重绘的素材。
- `prompt_pending` 轮只展示文字与生产摘要，以 `确认生成` 收尾，`formal_generation_count` 仍为 `0`。
- 确认后由生图模型一次完成整张海报，产生可查看的完整海报预览；默认 `formal_generation_count` 恰好为 `1`。
- 输出明确标记为生成式整图，不声称人物、截图、Logo 或中文逐像素保真。
- 若出现错脸、漏人、重复、乱码或明显视觉失败，记录失败并交给用户决定是否重做，不自动调用第二次正式生图。

### 通过所需直接证据

- `prompt_pending` 的完整 Prompt、风险披露和确认回复；
- 唯一一次正式海报生图的工具记录、输出文件和完整预览；
- 模式 A 的最终视觉 QA，以及 `formal_generation_count: 1`。

当前结果：`NOT VERIFIABLE`。尚未用当前版本完成一次隔离的模式 A 正式生图。

## 场景 3：模式 B 保真合成

### 前置条件与测试输入

先向新对话提供已核验的 `PersonMaterialSet` 及确认记录 `人物素材通过`，再提供虚构的多人 Brief、完整案例截图、原始 Logo 和固定中文。让 Agent 给出方向后回复：

> 选方向 1，用模式 B

Agent 展示完整 Prompt 与保护图层合成说明后再回复：

> 确认生成

### 预期停留阶段

- 正式生图前必须停在 `prompt_pending`。
- 只有位图底图溯源、保护图层验证和全部硬性 QA 通过后，最终才停在 `complete`；否则停在 `qa`、`handoff` 或负责阶段。

### 预期行为

- 最终确认内容同时包含“主视觉位图生成 Prompt”和“保护图层合成说明”，确认轮不生成排布预览，也不消耗正式海报生图。
- `production` 的第一项动作必须调用生图模型，先落盘一张由模型直接生成的 PNG、WebP 或 JPEG 艺术底图。底图包含场景、构图、材质、光影、前中后景、装饰语言和视觉动势，并为保护图层留下自然位置。
- SVG、HTML、Canvas、PPT、Sharp 绘图、规则矩形或头像网格不得先于位图底图运行，也不得充当底图或最终海报。
- 只有位图底图存在后，代码才能执行蒙版、等比缩放、位置与层级、阴影衔接、文字栅格化、格式转换、保护图层覆回和验证。
- 正式制作使用确认过的透明人物总图或独立透明抠图，以及原案例截图、原 Logo 和准确中文；不得把横版白底组合预览图作为矩形素材贴入海报。
- 生产收据至少记录 `visual_base_path`、`visual_base_format`、`image_generation_model_or_tool`、`visual_base_created_before_composite`、`protected_layer_ids` 和 `formal_generation_count: 1`。
- 最终必须提供完整海报预览。调整 Logo、截图或固定中文时只改独立图层，并证明非目标区域未改变，不能重新生成整张海报。

### 通过所需直接证据

- `prompt_pending` 的两段完整生产说明与 `确认生成`；
- 生图模型返回的底图文件、格式和时间／调用顺序证据；
- 后续保护图层清单、合成产物、逐项像素或哈希验证与完整预览；
- 无程序化底图的生产记录，以及 `formal_generation_count: 1`。

当前结果：`NOT VERIFIABLE`。尚未用当前版本证明“先生图位图、后保护合成”的完整顺序。

## 场景 4：平台没有生图模型

### 前置条件与测试输入

先提供已核验并明确回复 `人物素材通过` 的人物素材、虚构 Brief、保护素材和方向／模式选择。Agent 展示完整 Prompt 后，说明当前执行平台没有任何生图模型，再回复：

> 确认生成

### 预期停留阶段

`handoff`

### 预期行为

- 保留已经确认的人物素材、方向、模式和完整 Prompt，不把能力不足误写成用户未确认。
- 明确说明当前平台不能生成所需视觉底图或最终海报，`formal_generation_count` 为 `0`。
- 输出完整 Prompt、素材映射、三类人物素材记录、保护图层清单、目标位图格式、当前 QA、已知限制和下一执行工具要求。
- 不用 SVG、HTML、Canvas、PPT、Sharp、规则色块页、线框稿或头像网格替代生图底图，不把程序化信息板称为最终海报。
- 不声称人物、案例截图、Logo、固定中文或最终画面已经通过保真与视觉 QA。

### 通过所需直接证据

- 能力声明、完整 Prompt 和可恢复的交接收据；
- 证明没有正式生图调用、没有程序化底图或伪最终海报的工具记录；
- 显示最终停在 `handoff` 的完整对话。

当前结果：`NOT VERIFIABLE`。尚未用当前版本完成无生图能力的隔离降级测试。
