# 场景回归：傻瓜版完整海报默认流程

本文件验证“人物先确认、内容玩法先成立、默认 16:9 完整海报一次生成”的真实行为。静态字符串只能证明规则写进 Skill，不能证明 Agent 真的执行；两次确认、内容玩法、实际成图审美和局部精确修改都不能只靠关键词或 Regex 判定。

所有场景在新版完整前向测试完成前统一为 `NOT VERIFIABLE`，不得继承旧版模式 A／B、`prompt_pending`、排布稿或历史成图的 `PASS`。

## 执行协议

每个场景必须在隔离的新对话中执行：

1. 只向测试 Agent 提供当前 Skill 和当前场景所需的获授权虚构素材，不展示本文件的预期答案。
2. 保存完整对话、状态变化、两次用户授权、读取的 Skill 版本和全部工具调用。人物素材处理不计入正式海报生图次数。
3. 保存执行比例、正式生图次数、产物路径、可直接查看的预览、文件尺寸、文件哈希和实际成图检查记录。
4. 人物与案例贴合度必须对照源素材和 Brief 判断；仅出现“玩法”“横版”“高级感”等字样不能作为通过证据。
5. 视觉 QA 必须实际打开最终图片，在目标观看尺寸和高分辨率下检查；没有图片查看证据时，审美与成图 QA 一律为 `NOT VERIFIABLE`。
6. 精确后期修改必须保存修改前后图片、目标区域和解码后的图像差异；只有非目标区域差异像素为零，才能证明没有整图重绘。
7. 状态只使用 `PASS`、`FAIL` 或 `NOT VERIFIABLE`。发现失败时记录负责阶段，不自动消耗第二次正式生图。

## 场景 1：七位游戏剧情达人＋浅蓝夏日偏好

### 测试输入

- 七位获授权游戏剧情达人原图，每人一张代表案例；
- 一份要求达人矩阵招商、但没有指定固定版式的虚构 Brief；
- 用户首轮已经说明：“想要浅蓝夏日、轻松有剧情感，不要冷硬科技风。”

### 预期行为

- 先生成并只展示横版白底人物组合预览，核对七人身份、数量、重复、遗漏、身体完整、交叠、遮脸和残边；停在 `person_material_pending`。
- 用户回复 `人物没问题` 后才进入 `content_plan_pending`。
- 已给出视觉偏好，不重复询问颜色或感觉；方案卡说明浅蓝夏日偏好如何与 Brief、达人案例共同转译为配色、材质、自然光、氛围和装饰边界。
- 推荐方案和备选方案结构明显不同。每位达人都有玩法归属，每组都写清成员、案例依据、场景／人物关系、动作／互动／反转、产品进入方式和海报短文案。
- 用户回复 `选 1 生成` 后，直接调用一次完整海报生图；不得先生成空背景、排布稿或程序化信息板。
- 最终文件为默认 16:9 横版，人物、案例、主题、玩法与商务信息进入同一完整画面；`formal_generation_count: 1`。
- 实际成图必须看得出第一视觉、前中后景、人物与玩法连接和有效信息密度，不能只是浅蓝色卡片墙。

### 通过所需直接证据

- 白底人物预览、`人物没问题`、方案卡、`选 1 生成` 的完整对话；
- 未重复询问视觉偏好的对话轨迹；
- 七位达人和案例依据的玩法映射；
- 唯一一次正式生图调用、16:9 文件尺寸、直接预览和实际成图 QA。

当前结果：`NOT VERIFIABLE`（待新版前向测试）。

## 场景 2：数码 Brief 的 3:4 空玩法 badcase

### 测试输入

提供已确认的人物素材和一份“新机搭子”数码 Brief，但草案只有主题口号、“高级科技感”等抽象描述，执行参数误写为 `3:4`；用户没有明确要求竖版。

### 预期行为

- 预检拦截正式生图，停在 `content_plan_pending`，`formal_generation_count: 0`。
- 明确指出缺少成员归属、账号／案例依据、具体场景或人物关系、动作／冲突／互动／反转和产品自然进入方式。
- 将执行比例纠正为默认 16:9 横版；在玩法闭环和比例一致前不得生图。
- 不得把“数码”自动翻译成科技蓝、霓虹 UI、未来实验室、数据流或竖版空舞台。
- 不得用一张空背景图冒充“先完成了视觉部分”，也不得让用户为错误产物消耗一次正式海报生图。

### 通过所需直接证据

- 显示停在 `content_plan_pending` 的完整对话；
- 玩法预检失败项和 16:9 修正；
- 工具记录证明没有正式生图、没有 3:4 产物和程序化伪海报。

当前结果：`NOT VERIFIABLE`（待新版前向测试）。

## 场景 3：精确 Logo 修改

### 测试输入

向一张已经完成并通过 QA 的海报提出：

> 请在右上角新增两个原 Logo，透明底、左右并列、视觉大小一致，其他地方不要动。

### 预期行为

- 不重复人物确认或内容方案确认，不再次调用生图模型。
- 使用两个原 Logo 做局部图层修改；保持内部元素、颜色、比例和透明边缘。
- 导出尺寸与修改前完全一致；仅目标区域变化，目标区域确有 Logo 像素变化。
- 解码后的非目标区域图像差异像素数必须为 `0`；`formal_generation_count` 不增加。
- 若平台没有局部合成或图像差异验证能力，输出明确交接，不得整图重绘后声称“只改了 Logo”。

### 通过所需直接证据

- 原 Logo、修改前图片、修改后图片和目标区域坐标；
- 未发生新整图生图的工具轨迹；
- 前后图像差异图、尺寸对比和非目标差异像素计数。

当前结果：`NOT VERIFIABLE`（待新版前向测试）。

## 场景 4：严格保真自动后台路由

### 测试输入

用户明确要求：

> 人脸、案例和中文完全不变，案例文字和数据一个字也不能改，原 Logo 必须准确，用于正式提报。

同时提供获授权人物、完整案例、原 Logo、固定中文和 Brief。

### 预期行为

- 人物素材仍先确认；用户只回复 `人物没问题`，不选择技术模式。
- 方案卡仍以 `选 1 生成` 完成第二次也是最后一次确认；没有第三个 Prompt、排布或模式确认。
- Agent 在后台将 `generation_route` 自动设为 `strict_fidelity`。
- 正式生产先由生图模型生成一张非空艺术底图；底图必须包含完整场景、玩法关系、材质、光影、前中后景和视觉动势，不能只是留洞空背景。
- 艺术底图存在后才覆回确认过的人物、完整案例、原 Logo 和准确中文。默认仍为 16:9 横版，正式生图次数为 1。
- 最终保真检查必须对照源素材；不能只相信清单或 Agent 的文字声明。

### 通过所需直接证据

- 两次确认和没有技术模式选择的完整对话；
- `strict_fidelity` 后台路由记录；
- 艺术底图先于原素材覆回的调用顺序和文件证据；
- 源人物、案例、Logo、中文与最终图的保护验证，以及实际成图 QA。

当前结果：`NOT VERIFIABLE`（待新版前向测试）。

## 场景 5：无案例仍继续但披露贴合度有限

### 测试输入

用户只提供获授权人物原图和 Brief，没有案例截图、主页截图、代表作链接或账号介绍，并表示暂时无法补充。

### 预期行为

- 人物素材确认照常进行；不把案例设成阻塞项，也不反复追问。
- 明确说明达人玩法贴合度有限，不虚构账号机制、稳定笑点、人物关系或成功案例。
- 仍根据 Brief 已知场景形成最少完整玩法闭环：标题、明确成员、Brief 依据、具体场景／关系、动作／互动、产品进入方式和海报短文案。
- 方案卡将未知项和贴合度边界说清楚；用户回复 `选 1 生成` 后才允许默认 16:9 完整海报一次生成。

### 通过所需直接证据

- 无案例声明、有限贴合度披露和未虚构依据的内容方案；
- 两次确认、玩法预检记录和正式生图调用轨迹；
- 若完成生产，还需直接预览和实际成图 QA。

当前结果：`NOT VERIFIABLE`（待新版前向测试）。

## 场景 6：无生图能力只交付交接包

### 测试输入

从第一轮明确声明当前平台无生图能力，并提供已确认的人物素材、Brief、内容方案和素材映射，请 Agent 准备可恢复的交接包。

### 预期行为

- 不要求回复旧的 Prompt 确认词，不伪装成仍可在当前平台完成海报。
- `formal_generation_count: 0`，不生成 SVG、HTML、Canvas、PPT、Sharp、规则色块页或程序化信息板冒充海报。
- 交接包包含人物确认、视觉偏好、Brief 依据、玩法闭环、`generation_route`、完整执行 Prompt、素材映射、限制、当前 QA 和一个明确下一动作。
- 不宣称已经通过最终视觉 QA、人物保真或案例保真；没有实际成图时这些项目必须为 `NOT VERIFIABLE`。

### 通过所需直接证据

- 完整交接包和终态 `handoff`；
- 工具记录证明正式生图为 0，且没有程序化伪海报；
- 所有未生产、未看图、未验证事项均未被误报为 `PASS`。

当前结果：`NOT VERIFIABLE`（待新版前向测试）。

## 场景 7：Aime 评委一句话开始

### 测试输入

评委在 Aime 上传完整 Skill 压缩包，只发送：

> 帮我安装并告诉我怎么使用。

### 预期行为

- Skill 自动发送一次新手开场白，说明人物素材和案例图的作用，并给出多人示例与极简填写模板；不要求评委复制长启动 Prompt。
- 评委上传人物后，先生成一张横版白底人物组合预览，停在 `person_material_pending`。
- 用户回复 `人物没问题` 后，Aime 才整理 Brief、案例、风格和文字密度，形成两个方案。
- 用户回复 `选 1 生成` 后，Aime 只把当前 `LockedPosterSpec` 编译成简洁执行 Prompt，调用 Image2 正式生图一次。
- 不把整段聊天记录、已否决方向或平台操作说明交给 Image2。
- 最终必须是 16:9 横版，有具体玩法、信息层级、第一视觉和前中后景。

当前结果：`NOT VERIFIABLE`（等待用户在 Aime 实测）。

- 不走“新版—无字底图—代码叠字版—聚合底图—精装修版”的多次试错链。
