# 2026-08-31 生图优先流程独立测试记录

本文件只记录新版流程的直接证据。未真实运行或缺少图像／调用记录的项目必须保持 `NOT VERIFIABLE`，不能用静态规则代替行为证据。测试材料使用授权素材，提交记录只保留匿名 `Pxx/Cxx/Lxx` 编号，不保存本地绝对路径。

## person_first

- 目标：验证只收到人物／动物原图时，先产出人物素材并等待 `人物素材通过`，不先要求 Brief、方向或模式。
- 预期停止阶段：`person_material_pending`；不得出现海报排布确认门槛。
- 必须检查：用户只看到一张横版白底组合预览；后台保留同排布透明底人物总图；独立透明抠图只在需要单独移动、重组、修复遮挡或局部替换时按需生成。同步检查人数、身份、重复、遗漏、遮挡和边缘。
- 正式海报生图次数：`0`；人物素材处理不计入正式海报生图。
- 失败路由：人物身份、数量、边缘或透明通道失败时仍停在 `person_material_pending`；能力不足时进入 `handoff`。
- 当前结果：`PASS`（交互合同通过；实际抠图能力沿用已验证记录）。
- 直接证据：新的独立纯文本前向测试只向用户展示一张白底组合预览，把同排布透明总图明确为后台资产，并说明独立透明抠图只在后续需要单独移动或重组时按需生成；没有把三份产物变成三个确认项。既有隔离生产测试得到 2560×1440 RGB 白底预览、2560×1440 RGBA 透明总图及边缘 QA，证明身份保真、透明通道与素材台账能力可用。
- 核验结果：识别到 13 个可见主体（9 人、3 猫、1 狗），无新增、遗漏、重复或身份重绘；保留原始椅子、台面和组合关系，并明确记录细发丝、白色毛发可能带有原白底污染这一来源限制。
- 阶段与计数：停止在 `person_material_pending`，以 `人物素材通过` 为唯一下一步；`formal_generation_count: 0`。
- 可复核摘要：源图 SHA-256 为 `7dd489d2d59dda199d5523094ed205751e4c42fe69be148b22a27fb335843d77`，透明总图 SHA-256 为 `461d65415fd1506846be15b69ccb2cec01b8e6db64a38a5d82158fb19ce3f108`。

## mode_a_one_generation

- 目标：验证人物素材通过后，模式 A 清楚披露重绘风险；内部保留最少充分的完整执行 Prompt，用户默认只看一屏 `生成确认卡`，并在 `确认生成` 后只进行一次正式海报生图。
- 必经停止阶段：`prompt_pending`；不得出现海报排布确认门槛。成功终态为 `complete`。
- 必须检查：一屏生成确认卡、风险披露、内部完整执行 Prompt、完整海报预览、最终文件、明显错脸／漏人／乱码，以及是否自动重试。
- 正式海报生图次数：默认恰好 `1`；确认 Prompt 的文字轮次为 `0`。
- 失败路由：生成失败后停在 `qa` 或负责阶段，先报告问题，不自动调用第二次正式生图。
- 当前结果：`PASS`（流程合同通过，首张成品视觉 QA 未通过）。
- 直接证据：既有隔离生产对话先停在 `prompt_pending`，确认轮 `formal_generation_count: 0`；收到 `确认生成` 后只调用一次生图模型并保存 PNG，未自动重试。当前版本另以独立纯文本前向测试验证默认展示一屏生成确认卡、完整 Prompt 仅在用户回复 `查看完整 Prompt` 时展开。
- 产物核验：9 人、3 猫、1 狗均出现一次；主题、中文与内容边界通过；画面具有真实场景和商业海报感，不是 PPT 或卡片墙。
- 失败路由：首张产物因主标题强于已确认的 P01 第一视觉、实际尺寸 1672×941 而非 1920×1080，视觉／规格 QA 记为 `FAIL`；系统诚实退回 `production` 并停止，等待用户决定是否授权第二次正式生图。
- 阶段与计数：当前阶段 `production`；`formal_generation_count: 1`；产物 SHA-256 为 `016fa847166e16856118af96c95c4d2393409b2d6bef851d20f6708457f0ecb0`。

## mode_b_bitmap_then_layers

- 目标：验证模式 B 第一项生产动作是生图模型生成 PNG、WebP 或 JPEG 位图底图，随后才覆回人物、截图、Logo 和固定中文。
- 必经停止阶段：`prompt_pending`；不得出现海报排布确认门槛。成功终态为 `complete`，无法合成时为 `handoff`。
- 必须检查：底图文件与真实格式、生成工具／模型记录、先后顺序、保护图层表、非目标区域、完整海报预览和最终视觉质量。
- 正式海报生图次数：默认恰好 `1`；必须记录 `visual_base_path`、`visual_base_format`、`image_generation_model_or_tool` 与 `visual_base_created_before_composite`。
- 失败路由：程序化底图或顺序不可验证时停在 `production`；缺少所需能力时进入 `handoff`，不得伪装完成。
- 当前结果：`PASS`（生产链路与保护层验证通过）。
- 直接证据：正式制作的第一项动作由 OpenAI 内置生图模型生成 1672×941 RGB PNG 艺术底图；底图包含真实城市街区、光影、材质、前中后景和自然留位，不是 SVG、HTML、PPT、Canvas、规则矩形或头像网格。
- 合成顺序：底图落盘后，才用确定性合成覆回 P01 人物总图、C01 原案例截图、L01 原 Logo 与 T01/T02 中文；没有第二次正式生图。
- 保护验证：生产收据记录 `visual_base_created_before_composite: true`、`formal_generation_count: 1`；人物不透明像素、案例等比图层、Logo 不透明像素均匹配，底图与成品哈希不同。
- 视觉核验：成品具备城市场景、纸张拼贴、路径动势、环境光影与明确前后层次，未出现 PPT／程序化信息板观感；人物群像为主要视觉，案例和中文可读。
- 可复核摘要：底图 SHA-256 为 `2a4481dcd8920e836f5a090ebe31bdd64465fa737607cec005fee4882db9dcfb`，成品 SHA-256 为 `97fdc3b1c5b20b0fb8b33a5040440c72b78ed1e6b962e19d9732940f8a869114`。
- 边界：本次直接证据覆盖生产顺序、保护合成和最终视觉；人物确认门槛由 `person_first` 隔离场景单独验证，未用同一次生产再次消耗生图额度重复测试。

## no_imagegen_no_svg_fallback

- 目标：验证平台没有生图能力时只输出完整 Prompt、素材映射和交接包，不用 SVG、HTML、PPT 或程序化信息板冒充最终海报。
- 预期停止与终态：从首次能力判断直接进入 `handoff`；不得要求海报排布确认或再次经过 `prompt_pending`。
- 必须检查：能力说明、人物素材记录（白底预览、透明总图及按需独立抠图）、完整 Prompt、素材映射、目标位图格式、保护图层清单、当前 QA、下一执行工具要求，以及是否错误声称已生成海报。
- 正式海报生图次数：`0`。
- 失败路由：若输出程序化底图、伪最终海报或声称素材已保真通过，场景直接 `FAIL`。
- 当前结果：`PASS`。
- 直接证据：首次独立测试发现系统虽然进入 `handoff`，仍错误要求 `确认生成`；修复后用全新隔离 Agent 重跑。
- 修复后行为：从首次能力判断直接进入 `handoff`，输出完整 Prompt、素材映射、保护图层清单、目标位图格式、当前 QA 和下一执行工具要求；没有 `prompt_pending`，没有要求 `确认生成`。
- 禁止项与计数：未生成 SVG、HTML、Canvas、PPT、程序化色块页或伪最终海报；`formal_generation_count: 0`。
